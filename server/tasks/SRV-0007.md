---

## 1. 目标

修复 Redis 缓存导致社区帖子列表不及时刷新的问题，尤其是新帖子发布、审核通过、编辑更新或删除后，列表仍显示旧数据的场景。

- 帖子列表缓存失效策略要覆盖创建、审核、编辑、删除、置顶、精选、屏蔽等会影响列表结果的操作
- Redis key 和 cache version 语义要清晰，避免不同筛选条件、分页和排序之间互相污染或长期命中过期数据
- 新帖子出现后，社区广场列表应能及时显示，不需要等待缓存自然过期

---

## 2. 验收标准

- [ ] 新帖子创建并审核通过后，帖子列表立即可见
- [ ] 帖子编辑、删除、屏蔽、置顶、精选后，相关列表缓存会正确失效
- [ ] 不同分页、分类、搜索、作者、公会等筛选条件的列表缓存互不污染
- [ ] Redis 不可用或缓存失效失败时，接口能降级读取数据库且不影响发帖流程
- [ ] 为帖子列表缓存失效补充服务端回归测试或可复现验证脚本
