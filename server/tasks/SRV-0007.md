# SRV-0007: Redis 缓存优化与帖子列表刷新修复

| 属性 | 值 |
|------|-----|
| ID | SRV-0007 |
| 类型 | FIX |
| 优先级 | P1 |
| 状态 | DONE |
| 模块 | server/internal/service/post_list.go, server/internal/service/post_mutation.go, server/internal/api |
| 依赖 | - |

---

## 1. 目标

修复 Redis 缓存导致社区帖子列表不及时刷新的问题，尤其是新帖子发布、审核通过、编辑更新或删除后，列表仍显示旧数据的场景。

- 帖子列表缓存失效策略覆盖创建、审核、编辑、删除、置顶、精选、屏蔽等会影响列表结果的操作
- Redis key 和 cache version 区分筛选、分页、排序和查看者作用域
- 新帖子和结构性变更提交后立即刷新候选 ID 缓存

---

## 2. 验收标准

- [x] 新帖子创建并审核通过后，帖子列表立即可见
- [x] 帖子编辑、删除、屏蔽、置顶、精选后，相关列表缓存会正确失效
- [x] 不同分页、分类、搜索、作者、公会等筛选条件的列表缓存互不污染
- [x] Redis 不可用或缓存失效失败时，接口能降级读取数据库且不影响发帖流程
- [x] 为帖子列表缓存失效补充服务端回归测试

## 3. 实施记录

- 新增候选 ID 缓存服务和事务型失效服务；列表响应继续实时加载计数和状态字段。
- 全局结构变更使用全局版本失效，屏蔽和本地隐藏使用查看者级失效。
- 验证覆盖 `post_list_test.go`、`post_mutation_test.go`、`post_cache_invalidation_test.go`。
- 最终验证：`go test ./... -count=1`、`go vet ./...`、遗留缓存 helper 搜索均通过。
